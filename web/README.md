# Cydintosh web flasher artifacts

This directory contains the browser flasher page and generated firmware artifacts.

## Browser flasher

- `index.html`
- `manifest.json`
- `server.py`

The checked-in manifest exposes the primary board-specific **full-flash** images for ESP Web Tools:

| Board | Chip family | Image | Size | Bootloader offset inside image |
| --- | --- | --- | ---: | --- |
| ESP32-2432S028 CYD2USB | ESP32 | `full-flash-esp32-cyd2usb.bin` | 4MB | `0x1000` |
| Sunton ESP32-8048S043C | ESP32-S3 | `full-flash-esp32-8048s043c.bin` | 16MB | `0x0` |

Experimental artifacts such as `esp32-cyd2usb-mac512x384-rotfit` can be generated with the Makefile, but they are not exposed by `manifest.json` unless explicitly added.

The `feat/mac-lc-color` Tab5/ESP32-P4 Macintosh LC target is **not** a stable web-flasher artifact. It currently builds a diagnostic skeleton only, uses local-only `vendor/mac-lc.rom`, and should be flashed with the explicit Tab5 Makefile targets after the USB/JTAG device is visible.

## Recommended: full-flash images

Always use the board-specific full-flash images when flashing stable Mac Plus targets. These include
bootloader, partition table, firmware, patched ROM, and LittleFS filesystem in
one file. This is especially important because ESP32 and ESP32-S3 use different
bootloader offsets. The experimental ESP32-P4/Tab5 LC target has its own partition layout and is not part of the stable web-flasher manifest.

### Generate artifacts

```bash
# Existing ESP32 CYD2USB target
make stable-artifacts PIO_ENV=esp32-cyd2usb

# ESP32-S3 8048S043C target
make stable-artifacts PIO_ENV=esp32-8048s043c

# Optional experimental CYD2USB 512×384 rotated-fit target
make stable-artifacts PIO_ENV=esp32-cyd2usb-mac512x384-rotfit

# Tab5 LC diagnostic skeleton (not a stable web artifact)
make build-tab5-lc
make flash-tab5-lc
make flash-tab5-lc-rom
```

### Flash command

```bash
# Erase flash first (recommended for clean state):
esptool --port <serial-port> --baud 460800 erase_flash

# CYD2USB:
esptool --port <serial-port> --baud 460800 write_flash \
  0x0000 web/full-flash-esp32-cyd2usb.bin

# ESP32-8048S043C:
esptool --port <serial-port> --baud 460800 write_flash \
  0x0000 web/full-flash-esp32-8048s043c.bin
```

For command-line flashing, prefer the Makefile target because it uses the same
board selection variables as artifact generation:

```bash
make flash-stable PIO_ENV=esp32-cyd2usb SERIAL_PORT=<serial-port>
make flash-stable PIO_ENV=esp32-8048s043c SERIAL_PORT=<serial-port>
```

## Flash memory layouts

### ESP32-2432S028 CYD2USB (`partitions.csv`)

| Offset | Content |
| --- | --- |
| `0x001000` | Bootloader |
| `0x008000` | Partition table |
| `0x010000` | Application firmware |
| `0x210000` | Patched Mac Plus ROM |
| `0x230000` | LittleFS (`disk.img`) |

### ESP32-8048S043C (`partitions-16mb.csv`)

| Offset | Content |
| --- | --- |
| `0x000000` | Bootloader |
| `0x008000` | Partition table |
| `0x010000` | Application firmware |
| `0x410000` | Patched Mac Plus ROM |
| `0x430000` | LittleFS (`disk.img`) |

### ESP32-P4 Tab5 LC diagnostic layout (`partitions-esp32p4-tab5-lc.csv`)

| Offset | Content |
| --- | --- |
| `0x009000` | NVS |
| `0x00f000` | PHY/reserved |
| `0x010000` | Application firmware |
| `0x410000` | LC ROM partition, 1MB reserved for local 512KB `vendor/mac-lc.rom` |
| `0x510000` | `disk` LittleFS/data partition reserved for LC boot-media diagnostics |

This layout is documented for developers only and is not exposed by `manifest.json`.

## Individual artifacts (for reference / advanced use only)

Generated by `make stable-artifacts PIO_ENV=<env>`:

- `bootloader-<env>.bin`
- `partitions-<env>.bin`
- `firmware-<env>.bin`
- `littlefs-<env>.bin`
- `full-flash-<env>.bin` — recommended flashable image

`littlefs-<env>.bin` contains the current `data/disk.img` at runtime as `/disk/disk.img`.
Regenerate and reflash it whenever the disk image changes.

Legacy artifacts from earlier development may exist in this directory. Do not
use `merged-firmware-*` images unless you know exactly which offsets and
filesystem image they pair with.
